# AnyListen 原生账号歌单扩展 0.2.1

在原版 AnyListen 的「扩展管理 → 本地安装」导入 `hona-account-sync_v0.2.1.alix`。管理入口为「设置 → 扩展设置 → 账号歌单同步」。字体、字号、间距、复选框、按钮与输入框均由播放器原生组件渲染，没有另做管理 GUI。

## 现已提供

- 网易云、QQ音乐、酷狗账号登录按钮、WebDAV 设置、立即同步。
- 网易云使用官方网页手机号登录，不再让用户走曾返回 404 的旧验证码路径。QQ音乐保留腾讯官方 QQ/微信授权页。酷狗使用 AnyListen 原生手机号与验证码输入框。
- 平台数据以 `网易云账号`、`QQ音乐账号`、`酷狗账号`、`LX N 歌单` 四个原生在线歌单来源提供，可在播放器的在线资源中浏览、添加，并使用播放器已有在线歌单刷新功能。
- 歌单名称使用 `网易云·我喜欢`、`QQ音乐·每日推荐`、`酷狗·每日推荐`、`LX N·…` 等前缀。没有实际返回的数据不伪造为成功。
- 已在本机原版 AnyListen 0.9.0 实际通过「本地安装」安装并验证原生设置加载。登录组件连接、网易云官方登录窗口唤起与取消也已验证。没有使用新账号验证码验证三个平台的实际同步结果。

## 重要接口边界

检查上游 `packages/shared/extension-preload/src/apis/exposeAPI.ts` 后确认：虽然类型文件声明了 `MusicList`，实际 `music_list` 分支仍是 TODO，没有挂载 `api.musicList`。0.2.1 检测这一情况并使用真正开放的 `registerResourceAction` 在线歌单 API，不再因不存在的接口启动失败。

因此，原版目前**尚不能由插件自动创建/批量删除所有本地歌单，也不能由插件改写侧栏 Ctrl/Shift 行为**。相关归档和防重导入逻辑保留在源代码并用模拟 API 测试，但当前原版安装包不显示无效的批量按钮，也不将模拟通过标为原版功能完成。这部分需要上游公开歌单管理接口及原生多选事件支持。

## 无管理界面登录组件

现有扩展 API 不包含网页登录 Cookie、BrowserWindow、系统钥匙串或启动本机进程接口。网页登录仍需要独立更新的**无管理界面本机登录组件**。它只监听 `127.0.0.1:38481`，使用经用户确认的独立令牌，凭据通过 Electron safeStorage 加密。首次连接弹出系统原生确认；只有授权时打开平台官方页面。

`.alix` 是真正可安装的扩展，但它不是无需本机组件就能完成全部网页登录的单文件程序。没有组件时仍可以加载设置和已有歌单缓存。组件不替换播放器、不注入播放器 DOM、不修改安装目录、不直接操作播放器数据库，不设置系统自启动。

## 开发验证

```sh
npm ci
npm run build:helper
npm run build:extension
npm test
node scripts/package-windows.mjs
```

使用官方 `@any-listen/extension-kit` 构建签名包。本地 `.env` 保存签名私钥，不可提交或分享。组件发布包不包含管理 HTML/CSS。

测试覆盖：原生设置 schema、缺少 musicList 时的原版兼容、签名、模拟歌单归档/取消/恢复、WebDAV 格式、网易云验证码正确路径、酷狗 listid=0/收藏 type/日推数组结构。自动测试不能代替真实账号的数据验证。

推荐由各平台根据其账号历史生成，不自动把播放器本地喜欢/不喜欢回写平台。播放仍依赖用户已有的合法资源扩展。
