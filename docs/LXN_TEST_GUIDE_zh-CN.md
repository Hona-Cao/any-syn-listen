# LX-N 手机端 WebDAV 互通：Windows 独立测试版

本分支专门用于测试 **LX-N（souvenp 版本）安卓端** 与 Any Listen 的 WebDAV 歌单互通。**它不等同于原版 lyswhut LX Music 的同步服务器协议。**

## 安装

1. 进入本仓库 GitHub **Actions** 页面，打开 **LX-N isolated Windows portable (no Codex)**。
2. 在构建成功的运行页面 **Artifacts** 下载 `AnySynListen-LXN-Test-Windows-x64`，解压 ZIP。
3. 运行其中的 `AnySynListen-LXN-Test-...-portable.exe`，不需要安装。
4. 测试版使用独立的应用 ID、协议名和 `AnySynListenLXNTestDatas` 数据目录，避免与正式 Any Listen 混用。未进行 Windows 真实用户设备验收，切勿替换原版。

## 首次测试（建议仅拉取）

1. 在 LX-N 安卓端将歌单同步到自己的 WebDAV，确保远端路径存在 `/LX_Music/playlists.json`。
2. 建议首次测试使用不重要的歌单或隔离的测试目录。测试中可能上传、删除和覆盖歌单；本版**不会自动创建备份**。
3. 在测试版的 **设置 → WebDAV 同步** 输入服务器完整 URL、用户名和密码。**Any Listen 自己的 WebDAV 快照同步开关无需开启**；这两套功能独立。
4. 在同一页面的 **LX-N 手机端歌单互通** 中启用同步，目录使用 `/LX_Music/`，**先不要启用「允许双向写入」**。
5. 点击 **立即同步 LX-N**。首次操作只读取手机端 `playlists.json`，在本机生成 `LX-N · 试听列表`、`LX-N · 我的收藏` 和 `LX-N · 自建歌单名` 镜像。
6. 检查列表曲目数量、来源、歌名。手机端独有的本地文件路径不能跨设备播放。

## 双向写回（进阶测试）

在核对导入结果后，再开启 **允许双向写入**。编辑带 `LX-N ·` 前缀的镜像歌单，然后点击立即同步。添加新的普通歌单时，使用 `LX-N · ` 前缀会将该歌单视为需要同步的新 LX-N 歌单；普通 Any Listen 歌单不会被自动上传。

**冲突限制：** 如果检测到手机与电脑两侧的歌单均发生变化，程序拒绝静默覆盖。目前没有自动的三方合并、冲突解决器或严格 WebDAV 原子写入保证。不要在两端同时编辑，尤其不要在手机后台自动同步过程中进行写回操作。

同一 `playlists.json` 的 `playHistory`、`downloadTasks`、`tempList` 和未知字段会在写回时尽量原样保留，但必须在真实设备和服务端验证。不要对唯一一份珍贵歌单直接尝试删除或批量修改。

## 已知限制

- 只针对 LX-N 安卓端 `playlists.json` v2；**不是**官方落雪 LX Music 的 WebSocket 同步。
- 同步歌单元数据，不同步下载文件、账号登录态、播放历史或听歌进度。
- 默认约每三分钟检查一次；可手动点按钮。
- WebDAV 服务商对条件写入支持不一，仍存在极小的并发窗口。
- 代码构建与模拟协议测试通过，**不等于真实 Windows 和 LX-N 安卓设备联调已通过**。
- 尚未进行代码签名，Windows SmartScreen 可能弹出未知发布者警告；仅从你自己的 GitHub fork 构建页面下载。
- 完全不依赖 Codex 额度。GitHub Actions 使用 Node.js、pnpm、Electron Builder 构建。

开发分支：`feat/lxn-webdav-interop-clean`；代码审查：PR #8。不要在没有验证前合并到正式分支。


## 多台电脑提示“LX-N sync conflict”时

这是两台电脑对同一份 `playlists.json` 各自持有旧同步基准，或确实存在不同的歌单更改时的保护提示，**不代表坚果云 WebDAV 文件损坏**。新版本会先对比本地、云端的歌单内容；若内容相同，即使同步基准不同也会自动解除误报。

如果内容确有不同，设置界面会出现两种手动处理方式：

- **保留坚果云歌单**：读取当前 WebDAV `playlists.json`，更新本机 `LX-N ·` 镜像，不覆盖其他普通歌单。
- **保留本机歌单**：以本机 `LX-N ·` 镜像写回 WebDAV，仅在明确开启“双向写入”且再次确认后执行。此操作可能覆盖另一台电脑未同步的修改。

**两种方式都需要第二次确认，但新版本不会在任何一次上传、下载或冲突解决时生成本地备份文件。** 选择覆盖后，另一端未同步的修改可能无法恢复。

若 Any Listen 的“同步歌曲列表”和 LX-N 歌单同步同时开启：前者维护 `list/` 快照，后者维护 `playlists.json`，文件不会直接冲突，但两个同步引擎可能分别修改本地 `LX-N ·` 镜像。排障时可**暂时关闭 Any Listen 原生“同步歌曲列表”选项**，只测试 LX-N 互通；普通 Any Listen 歌单届时将暂停快照同步。

目录应以实际 WebDAV 文件位置为准。例如坚果云根目录下为 `lxmusic/playlists.json`，LX-N 目录就填写 `lxmusic`，并非必须是 `/LX_Music/`。

仍然存在普通 WebDAV 并发写入的竞态窗口；避免两台电脑同时执行覆盖。

## 同步产生的文件和空间占用

- **LX-N 兼容同步：** 只使用你设置的 WebDAV 目录中的同一个 `playlists.json`；读取和写回都不会创建按日期命名的额外远端副本。程序仍然会在电脑本地保留自己的歌曲数据库及同步基准哈希，但**不会创建同步备份文件**。
- **Any Listen 原生快照同步：** 如果同时开启上方原生 WebDAV「同步歌曲列表」和「同步不喜欢规则」，`list/snapshots/` 和 `dislike/snapshots/` 将生成独立快照。上游代码默认各最多保留 30 个历史快照，并额外保留正被设备引用的版本；超过上限会尝试清理未引用的旧快照。如果仅使用 LX-N，建议关闭原生快照同步。
- **坚果云文件历史：** WebDAV 写回同一个文件，但服务端是否保留历史版本、是否计入配额，属于坚果云的服务端策略，客户端不能保证或清除。
- **旧版本遗留的本地备份：** 更换本版不会删除之前已经创建的备份。若不再需要，可自行删除测试版数据目录里的 `lxn-conflict-backups` 文件夹。**仅删除这个精确名称的文件夹，不要删除整个 AnySynListenLXNTestDatas 数据目录**，否则可能丢失歌单、配置等。

## 多设备“只保存最新版本”的模式（2026-10-28 更新）

本分支新版进入 **LX-N 单文件模式** 后：

1. 每台 Windows 测试版保留正常工作的 SQLite 数据库和同步状态，但**禁用本地数据库每天、启动时和修改事件触发的自动备份**；异常配置文件也不另存 `.bak`。为了不隐藏错误，若数据库或配置文件损坏，程序保留原文件并报错停止，而不是自动生成备份或重新初始化。
2. 启用 LX-N 同步时会自动关闭 **Any Listen 原生的 WebDAV 同步开关**以及“同步歌曲列表”“同步不喜欢规则”，停止产生新的 `list/snapshots`、`dislike/snapshots`。**此前的历史快照不会自动删除**，不要在其他设备仍需要它们时贸然删除。
3. LX-N 兼容层仅对 **同一个目录的 `playlists.json`** 读取和覆盖，不创建新版本或带日期的同名副本；发生真正的多端编辑冲突时依然提示用户选择云端或本机版本。**“只保留最新”不能推导出“多设备同时编辑绝不丢数据”**。
4. **仅我们修改的 AnySynListen 测试程序受以上限制**。LX-N 手机应用自己的内部备份机制（如有）不在此修改范围；坚果云后台的文件历史机制由服务商控制，无法由这个客户端关闭。
5. 只有电脑端全部使用该版本并启用了 LX-N 单文件模式，才能避免旧版 Any Listen 在云端继续上传自己的快照。未迁移的普通 Any Listen 歌单不再通过原生 WebDAV 同步。
6. 不会自动清理历史文件。旧版遗留的 `db_backups/`、`lxn-conflict-backups/`，以及远端 `list/snapshots/`、`dislike/snapshots/` 需要用户在确认不再使用后自行清理。**不要删除整个数据目录**。

推荐设备使用方式：一台设备修改歌单并成功同步后，其他设备再打开并先拉取，然后再做修改。若家用电脑、办公室电脑、多个手机离线各自更改同一首歌单，当前版本不能自动保证所有修改均保留。

## 我的列表右键操作

- 右键列表空白处，选择“批量选择歌单”；右键某个歌单也可以从该歌单开始选择。
- 批量选择模式下，点击歌单行或复选框进行多选；右键空白处或列表行打开操作菜单。
- “批量编辑名称”会直接在列表行内编辑，使用列表上方的“保存/取消”完成操作。
- “批量删除”只允许普通自建歌单，并显示一次确认。
- “导入到其他列表”会在同一右键菜单中显示目标列表；复制会跳过目标中已有的歌曲，不删除来源歌单。
- 为避免跨设备本地文件路径失效，另一台设备创建的本地文件歌单不可选作批量导入来源。

不再使用独立的批量管理弹窗。歌单批量操作从“我的列表”右键菜单进入，名称直接在列表中编辑。
 
## 上方原生 WebDAV 为什么变灰

当前处于 LX-N 单文件模式时，上方“启用同步”可以点击；确认切换后软件会关闭 LX-N 单文件模式，启用 Any Listen 原生 WebDAV 快照协议。**两套模式不会同时自动运行**，因为原生快照会生成 `list/snapshots` 和 `dislike/snapshots`，与“云端只保存 playlists.json”不兼容。

若你的目标是手机和多台电脑共享同一份 LX-N 歌单，应继续使用下方 LX-N 模式。开启上方原生同步前，会明确提示它重新引入快照文件。
