# ADR 0001：LX-N 歌单库按最后成功提交版本覆盖

- 日期：2026-10-15
- 状态：产品决策已讨论确认；技术可行性与整体验收待验证
- 适用范围：AnySynListen 与**未经修改的** LX-N Music 通过 WebDAV 共享的 LX-N 歌单库
- 不适用范围：AnySynListen 原生歌单、网易云音乐、QQ 音乐、酷狗音乐的只读镜像

## 背景

用户期望 PC 对 LX-N 歌单的修改（包括删除）最终能在手机上体现，并希望省去复杂冲突合并操作。现有 AnySynListen `lxWebdav.ts` 对 `/LX_Music/playlists.json` 仅做只读镜像导入，无法回写；LX-N Music 自身包含本地操作队列和数据合并逻辑，因此未经修改的手机 App 并不保证严格执行本 ADR 的覆盖顺序。

## 决策

1. LX-N WebDAV 双向回写为**显式可选功能**，默认关闭。
2. 首次启用时，以 WebDAV 现有 LX-N 歌单库为初始权威状态；不能用 PC 旧镜像在首次连接时直接覆盖远端。
3. 双向同步只作用于**完整 LX-N 歌单库**：试听列表、我的收藏和 LX-N 用户歌单；与其他歌单源保持隔离。
4. 冲突原则采用完整库最后写入获胜（last-successful-commit-wins）。两端同时改变不同歌单也不做自动内容合并；最后成功写入远端的完整库状态覆盖之前的整库状态。这里的“最后”是提交先后，而非歌曲编辑时间。
5. 允许主动删除 LX-N 歌单并向另一个兼容设备传播。若手机端删除了历史每日推荐，即使 PC 已将同一来源歌单归档，也应随同步移除。
6. 按用户明确选择，**不自动保存恢复备份，不增加首次启用、强制覆盖和批量永久删除的危险操作确认弹窗**。因此历史更改可能不可恢复。
7. 即便不设确认与备份，必须验证远端数据和请求结果：网络中断、鉴权失败、格式损坏或不可信的空响应不能被判定为删除；不能用这些异常状态发起全库覆盖。
8. 不修改 LX-N Music 安卓应用。若其内部合并逻辑与本决策不同，只能保证 AnySynListen 侧的实现和可观测行为；移动端严格遵守最后提交获胜**不做不实承诺**。
9. 保留可见的同步结果、失败原因和重试状态，但不要求用户每次确认。

## 考虑的替代方案

- **逐歌单合并/冲突交互：拒绝。** 更可能保住并行更改，但不符合用户选择的简单全库覆盖模型。
- **同时修改 LX-N 安卓端：拒绝。** 可以建立统一的冲突协议，但新增维护一套客户端的成本，用户明确不希望修改。
- **自动备份和危险操作二次确认：拒绝。** 可降低误删风险，但用户明确要求省略。不能以隐藏备份或弹窗替代其选择。
- **只读镜像、不允许 PC 回写：未采用为最终目标。** 保留为默认安全模式，但不能满足删除传播。

## 后果与约束

- 一次较晚的完整库提交可能覆盖另一个设备尚未同步的改动；删除可能在无备份前提下不可恢复。
- 由于原版 LX-N Music 仍可能重放离线操作，跨客户端严格一致性未被保证，必须列为兼容测试和公开限制。
- WebDAV 并发写入可能竞争；实现阶段须分析服务端文件版本/ETag 能力和失败后的读回验证，不能仅依赖本地时钟。
- 歌单来源隔离是硬边界：LX 全库覆盖不得连带删除 AnySynListen 原生歌单或第三方账号镜像。
- 不实现自动备份不妨碍在隔离测试环境使用虚构测试歌单和测试文件验证数据损坏风险。

## 验证准则

- 只读默认开关不写远端；首次启用优先远端。
- 对两端不同歌单的并行修改，验证最终整库获胜行为，并明确记录手机原版与预期的偏差。
- 对 PC 删除、手机删除、手机离线重连、历史每日推荐删除及归档移除分别测试。
- API 失败、WebDAV 返回损坏文件和登录过期时，已有歌单不因错误而清空。
- 完整 LX 库覆盖不会触碰 AnySynListen 原生库和第三方音乐平台账户。
